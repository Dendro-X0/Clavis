# Design — v0.12.0 desktop fill & match

**Status:** done (v0.12.0)  
**Band:** v0.12.0  
**Owners:** `clavis-shell` (native fill + foreground probe), `vault-core` (optional match ranking only — no second crypto), `apps/web` (confirm UI)  
**Depends on:** v0.10 generator (optional “fill new password” later); stable `Entry.url`  
**Umbrella:** `specs/backend/post-0.9.0-friction-hygiene-umbrella.md`  
**Platform:** **Windows first**; macOS/Linux deferred or no-op with honest UI

## Goal

Reduce friction for desktop login **without** a browser extension or always-on keylogger: confirm-gated **autotype** into the focused window, plus **opt-in** suggestions from foreground window title (and best-effort browser title heuristics).

## Non-goals

- Browser extension / content-script autofill that phones home  
- Global keylogger or accessibility scrape of other apps’ fields without user gesture  
- Auto-fill without an explicit confirm step  
- Cross-platform parity in v0.12 (Windows-first is enough to ship the band)  
- Password health / HIBP (v0.11); attachments (v0.13)

## Features

### 1. Autotype into focused window (Windows)

| Piece | Contract |
|-------|----------|
| Trigger | Command palette / entry menu: **Type username**, **Type password**, **Type login** (user → Tab → pass), optional TOTP after |
| Confirm | Modal: target window title + which fields will be typed; Cancel default-focused |
| Mechanism | Prefer **SendInput** Unicode key events after focus steal is confirmed; no storing OS key hooks |
| Timing | Small configurable delays between chars / Tab (defaults conservative); cancel if vault locks mid-type |
| Failure | If fill API unavailable → clear error; never partial-claim success |
| Settings | `autotypeEnabled` default **false**; requires unlock |

### 2. Opt-in URL / app-title suggestions

| Piece | Contract |
|-------|----------|
| Probe | While unlocked + setting on: poll/read **foreground window title** (and process name if cheap) on demand or low-frequency while Health/list focused — **not** continuous background when locked |
| Match | Normalize title/URL-ish substrings against `Entry.url`, `Entry.title`, tags; rank and show ≤5 suggestions |
| URL reality | Without a browser extension, true URL is often unavailable — document **title heuristics only** for Chrome/Edge/Firefox window titles (`Page - Browser`) |
| Opt-in | `suggestFromForeground` default **false**; independent of autotype but fill still needs confirm |

### 3. IPC sketch

```text
get_foreground_window_info() -> { title, processName? }   // unlocked; scrub logs
autotype_text(text, options) -> ()                       // confirm already done in UI
autotype_login(entryId, mode) -> ()                      // shell loads secrets; UI never gets password for type path if possible
```

Prefer **shell loads secrets and types** so React never holds password solely for autotype. UI passes `entryId` + mode after confirm showing **title only**.

## Threat model (must land in `docs/threat-model.md`)

| Threat | Mitigation |
|--------|------------|
| Keystrokes to wrong window | Confirm dialog shows live foreground title; re-read title immediately before SendInput; abort if title changed |
| Title spoofing / lookalike apps | Heuristic only; never auto-fill; user confirms; document residual risk |
| Malware same-user while unlocked | Already out of scope; confirm + lock shorten window |
| Always-on accessibility abuse | No persistent hooks; event-driven fill only; setting default off |
| Clipboard dual-use | Autotype path should **not** require clipboard (avoid residue); keep copy path separate |
