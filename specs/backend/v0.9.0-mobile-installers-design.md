# Design — v0.9.0 mobile installers (Android + iOS)

**Status:** in progress (slices 2–5 done; slice 6 version bump pending)  
**Band:** v0.9.0  
**Owners:** `apps/mobile` (Tauri shells), **Signet** (`signet` CLI — self-sign / ship / checksums / release attach), `docs/platforms.md` + `docs/release-checklist.md`  
**Signing tool:** [Signet](https://github.com/Dendro-X0/Signet) — local docs: `E:/Experimental projects/Self-signed-distribution/docs/`

## Goal

Ship **sideloadable Android and iOS installers** on the GitHub Release for `v0.9.0`, alongside existing desktop bundles, using **Signet self-signing first** (`[ship] path = "self"`). Same `vault-core` / `clavis-shell` / `apps/web` stack as Phase C preview — distribution graduates from “dev only” to “download, verify, install.”

## Locked decisions

| # | Decision | Choice |
|---|----------|--------|
| 1 | Sign backend for 0.9.0 | **Signet self path** — not graduate (OV / Azure / notarize) |
| 2 | Android signing | **Signet keystore** (`.signet/android/`) + `signet android sign` / `signet build` — sideload cert ≠ Play App Signing |
| 3 | iOS packaging | Build `.app` via Tauri/Xcode → **`signet ios package`** → `.ipa`; Signet does **not** App Store–sign; free provisioning ~7 days if free Apple ID |
| 4 | Checksums / trust | Signet `SHA256SUMS` (+ optional minisign) + `TRUST.md` attach on release |
| 5 | Multi-OS orchestration | `signet.toml` `[platforms]` + optional `[[targets]]`; prefer `signet ship --ci` / `--collect` / `signet release` over inventing a parallel Clavis-only mobile sign path |
| 6 | Native `gen/` | **Regenerate** per machine / CI (`pnpm mobile:android:init` / `mobile:ios:init`); **do not commit** `apps/mobile/src-tauri/gen/` (already gitignored) |

## Non-goals (defer)

| Item | Why |
|------|-----|
| Play Store / App Store listing | Store policy — Phase D / later |
| Signet **graduate** path (OV / notarize) | After self-signed dogfood works |
| Auto-update channel | Separate band |
| Full share-sheet import | Follow-up |
| Second crypto stack | Forbidden |
| Clavis-owned reimplementation of `apksigner` / IPA zip | Use Signet |

## Success criteria

1. Tag `v0.9.0` attaches **Android** `.apk` signed with the project Signet sideload keystore (cert digest in `TRUST.md`).
2. Tag `v0.9.0` attaches **iOS** `.ipa` produced via `signet ios package` (or documented equivalent), with honest free/ad-hoc notes.
3. Release includes Signet-produced **`SHA256SUMS`** (and `.minisig` when sums key exists) covering desktop + mobile assets.
4. README / `docs/platforms.md` / release notes explain Signet verify / sideload install and OS warnings.
5. Device or emulator smoke: unlock → copy → lock.

## Architecture

```
crates/vault-core / clavis-shell / apps/web / apps/mobile
        ↓ build artifacts (tauri android|ios build, existing desktop)
Signet (signet.toml in Clavis root)
        ↓ discover → checksum → android sign / ios package → ship collect
GitHub Release (v0.9.0) + TRUST.md
```

### Root `signet.toml` (committed)

See repo-root `signet.toml`. Targets: `desktop` → `pnpm build:desktop`; `android` → `pnpm build:mobile:android`; `ios` → `pnpm build:mobile:ios`. Secrets under `.signet/` (gitignored); CI restores identity/keystore via GitHub secrets — Signet `docs/secrets-layout.md`.

```bash
pnpm mobile:android:init   # before first Android build
pnpm mobile:ios:init       # macOS + Xcode; before first iOS build
```

## Distribution matrix (v0.9.0)

| Platform | Build | Signet role | Honesty |
|----------|-------|-------------|---------|
| Desktop | Existing Tauri / current CI | Optional migrate to `signet build --target desktop` + host sign; may keep softprops attach for one release if dual-path | Self-signed / unsigned OSS as today |
| Android | `tauri android build` → APK | `signet android keystore` + `sign` / build discover | Local keystore ≠ Play App Signing |
| iOS | `tauri ios build` → `.app` | `signet ios package` → `.ipa` | Packaging ≠ App Store; free ID ~7-day provision |

## CI shape

Prefer Signet’s ship loop (see Signet `docs/ship.md`):

1. `signet ship --ci` → commit generated workflow (or merge its jobs into existing `ci.yml`).
2. Tag / `workflow_dispatch` builds desktop matrix + `ship-android` + `ship-ios`.
3. `signet ship --collect` merges artifacts → `signet release --tag v0.9.0`.

If Clavis keeps the current desktop `softprops/action-gh-release` path for one band, mobile jobs must still run Signet sign/package + attach — do not ship unsigned APKs and call signing “done.”
