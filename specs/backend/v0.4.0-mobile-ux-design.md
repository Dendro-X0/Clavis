# Design — Clavis v0.4.0 mobile UX

**Status:** done (v0.4.0)  
**Owners:** `apps/web` (gestures/Gate), `apps/mobile` (biometric plugin), shared UI via `clavis-shell` keyring

## Context

v0.3.0 shipped desktop usability (global search, palette, pins, icons). Desktop tag CI remains flaky and is **parked** for this band. v0.4.0 focuses on **mobile interaction** on the existing Tauri v2 mobile shell + shared web compact surface.

## Goals

| Goal | Decision |
|------|----------|
| Touch / quick actions | Compact only: hide granular Copy/User/Pass rows; **swipe right → copy login (user→pass)**; **swipe left → open details**; long-press for Copy all / User / Pass |
| Biometric unlock | OS biometric gate over stored keyring/Keystore secret; master password always recovers |
| Desktop | Keep button copy actions; no swipe requirement |

## Non-goals

- Share-sheet import, TOTP, autotype, file sync (Phase D)
- Unblocking macOS/Windows desktop CI as a prerequisite
- Redesigning desktop dashboard chrome

## 1. Compact entry gestures

- Gate on existing `useCompactSurface()` (`max-width: 767px`).
- Entry list/grid rows: horizontal swipe with ~56px threshold; cancel if vertical scroll dominates.
- Swipe right → existing `copyLoginSequence`.
- Swipe left → open entry editor.
- Long-press (or overflow control) → Copy all / User / Pass.
- Visual: sliding row with muted “Copy” / “Open” reveal — no nested card stacks.
- Non-compact: current Copy / Copy all / User / Pass buttons unchanged.

## 2. Biometric unlock

```
Gate → biometric available & enabled?
  yes → OS biometric prompt → read keyring secret → unlock IPC
  no / fail → master password field → unlock IPC
```

- Thin shell commands: `biometric_available`, `biometric_prompt_unlock` (prompt then reuse unlock/keyring path).
- Prefer a maintained Tauri v2 biometric plugin for Android/iOS; desktop may keep keyring-only path.
- Gate UI: “Unlock with biometrics” only when Settings `biometricUnlock` is on (default **off**) and OS biometrics are available; password always fallback.
- Settings: sole place to enable/disable; enabling requires master password to store in keyring; disabling clears the keyring secret.

## 3. Threat / platforms notes

- Biometric ≈ same trust as OS keyring when enabled.
- Optional FLAG_SECURE / screenshot mitigation: follow-up if not finished in this band.
- Update `docs/threat-model.md` and `docs/platforms.md` when implementing.
