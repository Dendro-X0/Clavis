# Design — Custom fields UI (+ Next.js 16)

**Status:** done  
**Owners:** `apps/web` entry editor (model already in `vault-core::CustomField`)  
**Depends on:** v0.6.0 shipped

## Context

`Entry.custom_fields: Vec<{ label, value }>` is persisted and scrubbed, but the Edit entry panel never exposes it. Users need extra login identifiers (second email, mobile phone) without overloading Username/Notes.

Username remains the primary login id (email or username — same field, as in most password managers).

## Goals

1. **Editor UX** — Add / edit / remove labeled custom fields; quick-add presets **Email** and **Phone**; copy per value.  
2. **Search** — Dashboard search matches custom field labels and values.  
3. **Next.js** — Bump `@clavis/web` from 15.5.x → **16.2.12** (current stable); keep `output: "export"`.

## Non-goals

- Typed field kinds (email/phone enums) or validation  
- Custom field templates / plugins (roadmap P3)  
- TOTP fields (separate band)

## Proof

- `pnpm --filter @clavis/web exec tsc --noEmit`  
- `pnpm --filter @clavis/web build`  
- Manual: add Email + Phone on an entry, save, reopen, search by phone digits
