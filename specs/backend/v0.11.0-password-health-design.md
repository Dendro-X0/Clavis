# Design — v0.11.0 password health

**Status:** done (v0.11.0)  
**Band:** v0.11.0  
**Owners:** `vault-core` (scoring), `clavis-shell` (IPC + optional HIBP HTTP), `apps/web` (report UI)  
**Depends on:** v0.10.0 soft-delete (exclude trash from active scores by default)  
**Umbrella:** `specs/backend/post-0.9.0-friction-hygiene-umbrella.md`

## Goal

Give unlocked users a **local, workspace-aware password health report** — reused, short, weak charset, common denylist — without uploading the vault. Optional breach check is **opt-in, gated, and never continuous**.

## Non-goals

- Cloud scoring accounts or “security score” product framing that implies continuous monitoring
- Forcing password changes or blocking saves of weak passwords
- Uploading vault plaintext / full hashes to any service
- Autotype / fill (v0.12); attachments (v0.13)
- Bundling a multi‑MB HIBP dump in-repo for v0.11 (prefer k-anonymity or tiny denylist)

## Features

### 1. Local health report (`vault-core`)

| Piece | Contract |
|-------|----------|
| Scope | Default: **active workspace**, **non-deleted** only. Option: all workspaces (still exclude trash unless `include_trash`) |
| Inputs | Entry passwords (and empty → skip / flag “empty password” for login/api types) |
| Findings | `reused`, `short`, `weak_charset`, `common` (denylist), optional `breached` |
| Output DTO | Entry **id**, title, workspace name, finding kinds, severity — **never password plaintext** |
| Denylist | Compact embedded common-password list (case-insensitive); offline always |

Heuristics (v0.11 defaults):

| Check | Rule |
|-------|------|
| Short | `password.len() < 8` (after trim); note if 8–11 as “moderate” optional — keep **short** = `< 8` only for noise control |
| Weak charset | Fewer than 3 of {lower, upper, digit, symbol} **and** length `< 14` |
| Reused | Exact string match across scored entries (case-sensitive) |
| Common | Exact match against embedded denylist (lowercase compare) |
| Empty | Login / API / Custom with empty password → `empty` finding |

### 2. Optional breach check (HIBP k-anonymity)

| Piece | Contract |
|-------|----------|
| Default | **Off** |
| Gates | `allowNetwork == true` **and** `checkBreaches == true` |
| Algorithm | SHA-1 hex of password → query `https://api.pwnedpasswords.com/range/{prefix5}`; match suffix locally |
| UX | Explicit “Check breaches now” on Health panel (not background polling) |
| Failure | Network/error → toast; do not invent breach positives |
| Owner | HTTP in `clavis-shell` (same as favicons); hash helpers in `vault-core` |

**Not** continuous monitoring — copy in UI: one-shot check while unlocked.

### 3. UI

| Piece | Contract |
|-------|----------|
| Entry | Sidebar / palette “Password health” |
| Report | Grouped findings; click opens entry editor |
| Scrub | No passwords in React report state; clear panel on lock |
| Settings | `checkBreaches` under Network section; disabled unless `allowNetwork` |

## Threat / hygiene notes

- Report computation keeps secrets in Rust; UI receives ids/titles only.
- HIBP range query reveals a 5-char SHA-1 prefix to Have I Been Pwned — document as intentional privacy tradeoff when user opts in.
- Soft-deleted entries excluded by default so trash does not inflate reuse.
