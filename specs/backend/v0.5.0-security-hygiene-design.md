# Design — Clavis v0.5.0 security & memory hygiene

**Status:** implementing (Rust scrub in progress)  
**Owners:** `crates/vault-core`, `crates/clavis-shell`, `apps/web` (Gate / editor / copy paths), Settings  
**Depends on:** v0.4.0 shipped

## Context

Roadmap P0: *Memory hygiene audit (zeroize, lock drops key)*. Baseline today:

| Area | Current | Gap |
|------|---------|-----|
| `VaultKey` | `Zeroize` + `ZeroizeOnDrop` | Good |
| `VaultSession::drop` | Zeroizes key bytes | Document plaintext (`VaultDocument` / entry `String`s) stays until drop; no scrub of encode/decode buffers |
| Frontend secrets | React state holds master password (Gate) and entry passwords (editor / copy) | No explicit clear after use; GC is best-effort only |
| Auto-lock | `autoLockSeconds` (default 300); idle on `pointerdown`/`keydown`; lock when `document.hidden` | No settings for hide vs idle-only; no Tauri minimize/focus hooks; “system idle” ≠ app input idle |

Honest limit: **JS cannot reliably wipe heap strings**; we shorten dwell time and avoid retaining secrets outside the active editor. Rust can scrub owned buffers with `zeroize`.

## Goals

1. **Rust memory hygiene** — key material and short-lived plaintext buffers scrubbed on drop / after use in `vault-core` (and shell paths that touch passwords).
2. **Frontend sensitive lifecycle** — clear Gate / settings password fields after unlock or failed attempt; clear editor password when closing/locking; avoid keeping full entry secrets in list state (summaries stay username-only); after copy, drop fetched secret locals ASAP. **Done** (helpers in `lib/sensitive.ts`; Gate/Settings/page lock paths)
3. **Auto-lock policy** — keep configurable idle timeout; make hide/blur/minimize lock **opt-in or configurable** (default: idle lock on; lock-on-hide remains available); document behavior in Settings + threat model.

## Non-goals

- Perfect anti-forensics against a compromised OS / debugger  
- mlock / Secure Enclave wrapping of vault key (later)  
- FLAG_SECURE / screenshot blocking (separate band)  
- Changing Argon2 params / vault format version (unless scrubbing forces a tiny API-only change)

## 1. Rust (`vault-core`)

- Audit `encode_vault` / `decode_vault` / `encrypt`/`decrypt` callers: zeroize temporary `plaintext` `Vec<u8>` after encrypt/decrypt (and after JSON parse where owned). **Done**
- Prefer `Zeroize` on owned password wrappers at IPC boundary where shell still holds `String` briefly — document that Tauri IPC strings are OS-managed; clear Rust copies after `open_vault_file` / `store_keyring_secret`. **Done** (shell commands zeroize owned passwords)
- On `lock` / `Drop`: continue zeroizing key; optionally clear in-memory entry password fields in the dropped document (belt-and-suspenders). **Done** (`scrub_secrets` + salt zeroize)
- Proof: unit tests that exercise lock/drop paths; document residual risk (allocator may copy). **Done** (`scrub_secrets_clears_sensitive_fields`, `lock_drops_session_and_vault_remains_readable`)

## 2. Frontend sensitive lifecycle

| Surface | Rule |
|---------|------|
| Gate | Clear password/confirm state after success or handled error; never log secrets |
| Settings (bio / change password) | Clear password inputs after save / cancel |
| Entry editor | On lock, close editor and replace form with empty defaults; on discard/close, clear password field |
| Copy login / user / pass | Fetch entry → copy → do not stash password in component state; prefer ephemeral locals |
| List / search | Keep `EntrySummary` without passwords (already) |

Helpers: small `clearSensitiveString` / overwrite pattern is **documentation-only** in JS (immutable strings); real control is **drop references** + lock clearing UI state.

## 3. Auto-lock & idle

Settings (names illustrative):

| Setting | Default | Behavior |
|---------|---------|----------|
| `autoLockSeconds` | `300` | Existing; minimum floor kept |
| `lockOnHide` | `true` | Matches prior `visibilitychange` lock; user can disable in Settings |

- Idle = app input activity (pointer/key), not OS “system idle” API in v0.5.0 unless a small Tauri plugin is free.
- On any lock path: call `api.lock()`, clear editor/form secrets, refresh Gate.
- Compact/mobile: same policy; backgrounding WebView should hit `visibilitychange` when `lockOnHide`.

**Status:** Done (Settings UI + `AppSettings.lockOnHide`)
