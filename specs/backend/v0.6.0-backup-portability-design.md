# Design — Clavis v0.6.0 backup portability & vault durability

**Status:** done (v0.6.0)  
**Owners:** `crates/vault-core` (format/persist), `apps/web` Settings import/export UX  
**Depends on:** v0.5.0 shipped

## Context

Roadmap already lists **Argon2 params / KDF versioning** (P1) and Phase D interop. Two product goals for this band:

1. **Encrypted backup UX** — make KDF choice visible and trustworthy on export/import.  
2. **Durability** — keep `vault.km` corruption-resistant across crash/power loss.

### Baseline (already true)

| Area | Today |
|------|--------|
| Cipher | AES-256-GCM |
| KDF | **Argon2id** (params stored in `vault.km` header: `m_cost`, `t_cost`, `p_cost`) |
| Defaults | `m_cost=19456`, `t_cost=2`, `p_cost=1` (`crypto.rs`) |
| Persist / create / password change | `write_all_atomic` → write `*.km.tmp`, `sync_all`, `rename` over target |
| Encrypted backup | Same `vault.km` blob format (`export_encrypted` / `import_encrypted`) |
| UI | Settings export/import shows KDF summary; peek + warn + Upgrade KDF when weaker |

So this band is mostly **transparency + hardening + optional strengthen**, not inventing Argon2 or atomic writes from scratch.

## Goals

### 1. Key derivation transparency (export / import)

| Surface | Behavior |
|---------|----------|
| Export encrypted backup | Show: algorithm **Argon2id**, current params (memory MiB, iterations, parallelism), AEAD **AES-256-GCM**. Confirm before write. |
| Import encrypted backup | After successful open (or via header-only peek): show KDF params from the file. If weaker than app default, warn and offer **re-wrap with current defaults** on next persist / optional “Upgrade KDF” action. |
| Settings / docs | Short note that backups are the same format as `vault.km`; portable across Clavis versions that understand `VERSION`. |

**API sketch (vault-core / shell):**

- `peek_vault_kdf(path|bytes) -> { algorithm: "argon2id", mCost, tCost, pCost, version }` — parse header only (no password).  
- Optional: `export_encrypted` already copies bytes; UI reads active session params via `get_settings`/`vault_status` extension or new `vault_crypto_info` command exposing session KDF.

**Non-goals for 0.6.0:** user-editable custom Argon2 sliders (can be 0.6.1); multiple KDF algorithms; password strength meter on backup password alone.

### 2. Atomic writes audit & harden

Keep `write_all_atomic` as the **only** write path for `vault.km` and encrypted backup destinations when Clavis owns the write.

Checklist:

- [x] Grep: no direct `File::create(vault.km)` / non-atomic overwrite outside `write_all_atomic`.  
- [x] Windows: aside-to-`.bak` then rename (restore bak on failure).  
- [x] Always `sync_all` on temp file before rename; parent directory `sync_all` best-effort.  
- [x] On open/create/import: delete stale `*.tmp` / leftover `*.bak`; restore from `.bak` if primary missing.  
- [x] Proof: unit tests for replace, orphan tmp, crash-mid-write, bak recovery.

Export to user-chosen path should also use atomic write when overwriting an existing file.

## Non-goals

- Phase D file sync / Syncthing  
- Changing magic/`VERSION` unless KDF upgrade requires a documented bump (prefer same VERSION + stronger params in header)  
- Store signing / notarization
