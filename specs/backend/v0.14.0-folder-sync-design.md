# Design — v0.14.0 optional folder sync (vault.km)

**Status:** design (ready to implement)  
**Band:** v0.14.0 — Phase D first slice  
**Owners:** `clavis-shell` (data-dir UX, external-change detection, IPC), `apps/web` (Settings + unlock messaging), `docs/*` (threat model / platforms)  
**Depends on:** v0.10 soft-delete, v0.13 snapshots/attachments (lifecycle owners exist)  
**Umbrella:** `specs/backend/post-0.9.0-friction-hygiene-umbrella.md` · Phase D in `docs/roadmap.md`

## Goal

Let a user keep Clavis’s **data directory** (or an equivalent synced root) in a **user-owned folder** (USB, Syncthing, cloud-synced directory) so `vault.km` moves between machines **without** a Clavis cloud, accounts, or entry-level merge.

## Non-goals (this band)

- Clavis-operated sync / relay / accounts  
- Bidirectional Bitwarden / KeePass live sync (CSV import already exists)  
- Entry- or field-level CRDT / three-way merge UI  
- Watching mid-write temp files as truth (`vault.km.tmp`, `.bak`)  
- Store signing / notarization / Play / App Store (later Phase D)  
- Auto-merge of concurrent unlocked edits on two devices  

## Product stance

| Choice | Decision |
|--------|----------|
| Sync product | **User folder** — document Syncthing / OS cloud folders; Clavis does not ship a sync daemon |
| Conflict | **Last-write-wins on the whole `vault.km` ciphertext blob** |
| While unlocked | External change → **force lock** (or refuse persist) + clear message; never silent merge into the open session |
| Attachments | **Included when the sync root is the full data dir** (`attachments/` travels with the vault) |
| Snapshots | **Local-only by default** — document that `snapshots/` need not be synced (large; restore is machine-local); if user syncs whole `data/`, snapshots ride along without special UI |
| Config | `config.json` may sync with the folder (theme, retain days); fingerprint `lastVaultSha256` is expected to churn across devices — treat mismatch as **expected after peer write** |

## Recommended implementation shape (smallest)

Prefer **reuse `set_data_dir` / portable vs custom path** over inventing a second mirror of `vault.km`:

1. **Settings → Data folder** — clarify copy: “Point this at a folder you sync (Syncthing, cloud, USB). The whole data directory — especially `vault.km` and `attachments/` — must stay together.”
2. **External change detection** while the app is open:
   - On **window focus** and on a light **poll while locked** (e.g. 5–15s), hash `vault.km` (same SHA-256 path as fingerprint).
   - If hash ≠ last known for this process:
     - **Locked:** refresh status; surface existing `vaultFingerprintChanged` gate warning (tune copy for “another device or sync updated the vault”).
     - **Unlocked:** **lock immediately**, scrub session, then show the same warning on the gate. Do **not** keep writing the in-memory session over the peer blob.
3. **Persist safety:** before `persist()`, re-check on-disk hash; if drifted since session open / last record, abort persist, lock, warn (“Vault changed on disk; your unsaved edits were not written”).
4. **Docs:** `docs/platforms.md` + README short “multi-device via folder” section; honesty about LWW and concurrent edit loss.

Optional stretch (same band only if cheap): “Open synced folder…” picker that calls existing `set_data_dir` + confirm relocate copy semantics already used today.

## Compatibility with trash & snapshots

| Concern | Rule |
|---------|------|
| Soft-delete | Lives inside `vault.km` JSON → LWW blob carries trash state |
| Purge / retain-days | Runs on unlock against the **adopted** on-disk blob after fingerprint accept — never purge then overwrite with stale peer |
| Attachments | Soft-delete leaves sidecars; purge deletes `attachments/{entry_id}/`. Syncing only `vault.km` **without** `attachments/` leaves broken downloads — **product copy forbids vault-only sync** for attachment users |
| Snapshots | Restore replaces live `vault.km` locally; if a peer syncs an older blob afterward, LWW applies — user education only |
| Portable migrate | Fix/follow-up: `make_data_dir_portable` should copy `attachments/` (and optionally `snapshots/`) — track as atomic slice if still missing |

## Threat model rows (add with impl)

| Threat | Mitigation |
|--------|------------|
| Sync folder exposes ciphertext to cloud provider | Same as portable USB — AEAD at rest; no plaintext; document provider access to ciphertext |
| Two unlocked editors → silent loss | Force lock on external change; abort persist on drift; LWW documented |
| Syncing `.tmp` / partial writes | Ignore non-`vault.km` as vault truth; atomic replace already used |
| Fingerprint warning fatigue | Distinct copy when change is “expected sync”; still require unlock with master password |

## Proof plan

| Layer | Check |
|-------|--------|
| L1 | `cargo test -p vault-core` · `cargo check -p clavis-shell` · `apps/web` `tsc` |
| L2 | Point data dir at temp folder; unlock; externally replace `vault.km` while locked → gate warns; replace while unlocked → auto-lock + warn; edit + external replace before save → persist aborted / lock |
| L3 | Manual two-folder Syncthing (or copy) smoke on two machines if available |
| Claim | **Implemented** only with L1+L2; not “merge-safe” or “cloud backup product” |

## Atomic slices

1. **This design** + threat-model stub + roadmap pointer (docs only)  
2. Settings / platforms copy for “synced data folder” + portable migrate copies `attachments/`  
3. External hash check on focus + locked poll; unlocked → force lock  
4. Persist-time drift abort  
5. Gate copy polish for sync-expected fingerprint change  
6. Version bump **0.14.0** + release notes when slices 2–5 land  

## Out of band (later Phase D)

- Explicit merge UI / keep-both  
- Bitwarden / KeePass bidirectional  
- Store signing / notarization  
- Dedicated “mirror vault.km only” helper if portable install must stay separate from sync root
