# Design — v0.13.0 vault richness

**Status:** done (v0.13.0)  
**Band:** v0.13.0  
**Owners:** `vault-core` (entry model + attachment lifecycle hooks), `clavis-shell` (snapshots dir, attachment I/O, IPC), `apps/web` (UI)  
**Depends on:** v0.10 soft-delete / purge owners  
**Umbrella:** `specs/backend/post-0.9.0-friction-hygiene-umbrella.md`

## Goal

Add **local** vault depth without cloud: dated encrypted snapshots, per-entry encrypted attachments (size-capped, trash-aligned), and clearer structured notes (markdown + searchable).

## Non-goals

- Clavis cloud backup / sync (Phase D)  
- Unlimited blob storage or media gallery  
- Second crypto stack or plaintext attachment files  
- Collaborative editing / CRDT notes  

## Format decisions

| Feature | Layout | Rationale |
|---------|--------|-----------|
| Snapshots | `data/snapshots/vault-YYYYMMDD-HHMMSS.km` — full `vault.km` byte copy | Same AEAD blob; atomic restore; no schema change |
| Attachments | Metadata on `Entry`; ciphertext sidecars under `data/attachments/{entry_id}/{att_id}.enc` using vault session key + per-file nonce | Keeps large bytes out of JSON; purge deletes sidecars |
| Notes | Keep `Entry.notes`; add `notes_format: plain \| markdown` (default `plain`) | Backward compatible; search already can include notes |

Encrypted **export** remains a copy of `vault.km` only — attachment sidecars are **not** inside the blob. Snapshot restore restores the document; attachment files remain unless purged with entries. Document this in UI/docs.

## Features

### 1. Snapshots

| Piece | Contract |
|-------|----------|
| Create | Unlocked: write dated copy of current `vault.km` into `data/snapshots/` |
| List | Name, size, mtime |
| Restore | Confirm → replace live `vault.km` → reopen session (or lock + instruct unlock) |
| Retain | Settings `snapshotRetain` (default 10); prune oldest on create |
| Owner | `clavis-shell` paths + IPC; no vault-core schema change |

### 2. Attachments

| Piece | Contract |
|-------|----------|
| Cap | Default **256 KiB** per file; max **5** per entry (constants in core/shell) |
| Meta | `Entry.attachments: Vec<AttachmentMeta { id, name, mime, size, created_at }>` |
| Bytes | `attachments/{entry_id}/{id}.enc` — AES-256-GCM with session vault key (nonce prepended) |
| Soft-delete | Entry soft-delete leaves sidecars; **purge / empty trash** deletes entry attachment dirs |
| Restore entry | Sidecars untouched (still present) |
| UI | Editor: list / add (pick file) / download / remove meta+file |

### 3. Structured notes

| Piece | Contract |
|-------|----------|
| Format | `notes_format`: `plain` \| `markdown` (serde default `plain`) |
| UI | Note type (and optional toggle): markdown textarea + simple preview |
| Search | Include `notes` in client filter (if not already) |

## Threat / hygiene

- Attachment plaintext only while unlocked in memory/temp for download; wipe temp paths.  
- Snapshots are full vault ciphertext — same sensitivity as `vault.km`; store only under app data dir.  
- Markdown notes are still secrets in the vault (scrub with entry).
