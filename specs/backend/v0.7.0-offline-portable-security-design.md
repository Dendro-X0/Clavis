# Design — Clavis v0.7.0 offline-first portable security

**Status:** done (v0.7.0)  
**Owners:** `crates/clavis-shell` (paths, settings, IPC), `apps/web` Settings + entry editor  
**Depends on:** v0.6.0 shipped

## Honest boundary

Clavis cannot stop malware that already runs as the same user while the vault is unlocked. This band shortens exposure, keeps encrypted data with the app folder, and signals unexpected vault-file changes. No antivirus claims.

## Goals

### A — Portable / USB migrate

| Surface | Behavior |
|---------|----------|
| Non-portable warning | If `data-location.json` points outside `{exe}/`, Settings warns that absolute paths break plug-and-play |
| Make portable | Copy `vault.km`, `config.json`, and `icons/` into `{exe}/data/`; remove override; lock session |
| Portable kit copy | Explain: copy entire install folder (app + `data/`) to USB/another PC |

Overwrite: if portable `data/vault.km` already exists and differs from source, require confirm.

### B — Offline-first network

| Setting | Default | Behavior |
|---------|---------|----------|
| `allowNetwork` | `false` | Master gate for outbound HTTP |
| `fetchFavicons` | `false` | Only fetches when `allowNetwork && fetchFavicons` |

`fetch_entry_icon` returns early (no ureq) unless both are true. Cached icons may still be read from disk.

### C — Integrity + lock hardening

| Feature | Behavior |
|---------|----------|
| Vault fingerprint | SHA-256 of encrypted `vault.km` bytes stored as `lastVaultSha256` in `config.json` after unlock/persist; mismatch on next unlock → warning dialog (once per unlock) |
| Hold-to-reveal | Password fields masked; reveal only while control is pressed |
| Portable + keyring | Warn when portable and `biometricUnlock` is on |
| Clipboard default | New installs: `clipboardClearSeconds = 15` (existing configs unchanged via serde default only on missing key — use new Default impl) |

Fingerprint is a tamper *signal*, not a signed vault format.

## Non-goals

- Antivirus / process monitoring  
- Hardware-key unlock / format VERSION bump  
- USB-eject auto-lock  
- Claims of same-user memory protection while unlocked  

## API sketch

```text
get_data_dir_info -> { path, portable, appRoot? }
make_data_dir_portable(overwrite: bool) -> DataDirInfo
unlock / create -> { ..., vaultChanged: bool }  // or separate check_vault_fingerprint after unlock
record_vault_fingerprint() // internal after persist
```

Prefer: `unlock` / `create_vault` / successful persist update fingerprint; `unlock` returns `vaultFingerprintChanged: bool` when prior hash existed and differs.

## Proof

- `cargo test -p vault-core` · `cargo check -p clavis-shell` · web `tsc`  
- Make-portable clears override  
- `allowNetwork=false` → no network in fetch path  
- Hold-to-reveal; mismatch warning once
