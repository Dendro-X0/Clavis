# Design — v0.19.0 desktop background / tray

**Status:** implemented (v0.19.0 band)  
**Band:** v0.19.0  
**Owners:** `apps/desktop` (tray + close-to-hide), `clavis-shell` (`runInBackground` setting + lock), `apps/web` (Settings + lock event)  
**Platform:** desktop only (Windows / macOS / Linux). Mobile unchanged.

## Goal

Keep the Clavis process alive when the main window is closed, via a system tray icon, so the user can reopen quickly without fully quitting. Vault security defaults stay: **lock-on-hide remains on**, so hiding to tray locks the session unless the user opts out.

## Non-goals

- Always-on unlocked vault in RAM (that requires turning off `lockOnHide`)
- Mobile background execution / iOS background modes
- Global hotkey to summon the window (can follow later)
- Autostart at OS login (out of band)

## Behavior

| Action | With `runInBackground` (default **true**) | Off |
|--------|-------------------------------------------|-----|
| Titlebar Close / Alt+F4 / window close | Hide window; process stays; tray remains | Destroy window; process exits |
| Tray left-click or **Show Clavis** | Show, unminimize, focus | n/a |
| Tray **Lock vault** | Drop session in Rust; emit `vault-locked` so UI returns to Gate | n/a |
| Tray **Quit** | Lock session, then `app.exit(0)` | n/a |
| Second app launch | Single-instance: focus existing window | Same |

## Settings

`AppSettings.runInBackground: bool` — serde `runInBackground`, default **true**. Desktop Settings → Lock & clipboard. Hidden on compact/mobile.

## Security

- Hiding the window fires `visibilitychange` → existing `lockOnHide` path locks if enabled.
- Tray Quit always locks first so key material is dropped before process exit.
- Threat model: background process with ciphertext + optional unlocked RAM only if `lockOnHide` is off.

## Proof

- L1: `cargo check -p keys-manager`; web `tsc --noEmit`
- L3 (manual): Close → tray; Show; Lock; Quit; second launch focuses window
